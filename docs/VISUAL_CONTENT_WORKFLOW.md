# Visual Content Workflow

Use this workflow for Knowledge Base articles with food imagery, quantitative
comparisons, or explanatory charts. The preferred result is concise prose,
readable tables, useful charts, and consistent ingredient photography.

## Separate three layers

| Layer | Source of truth | Production method |
| --- | --- | --- |
| Nutrient values and units | Checked public data, with exact food entries and preparation states | A small committed JSON snapshot |
| Values, labels, axes, percentages and chart geometry | The snapshot and documented calculation rules | HTML/CSS or SVG generated by code |
| Ingredient appearance | An ingredient-specific visual brief | Built-in imagegen; inspect the result before use |

Generate the food imagery, not the data chart. Put quantitative labels in code,
not inside generated photographs. Never infer measured portions from an image.

## Image treatment

- Use a distinct, recognizable ingredient image for each food; avoid emoji as
  substitutes. Peas and edamame need separate images with different shapes.
- For chart thumbnails, use isolated, realistic food photography with a genuine
  transparent background, soft light, natural colour and generous margins.
- Keep lighting, perspective and treatment consistent across the ingredient set.
- Use a warm ivory setting for editorial food photographs that accompany an
  article. Chart cutouts remain transparent so they match the page background.
- Use the built-in imagegen tool. Read the available imagegen skill when starting
  a new generation task. Generate one asset per ingredient, with a shared style
  brief and an ingredient-specific subject description.
- Inspect ingredient identity, anatomy, edges and transparency. A generic leaf,
  bean, or mushroom is not an adequate substitute for the named ingredient.
- Copy selected results into the repository. Keep the original generated file;
  make small, optimized PNG derivatives for thumbnails, preserving alpha and
  aspect ratio. The current ingredient assets use a maximum edge of 256 px.
- Save the final prompts and production method beside the assets. Identify
  generated images in the article without adding process detail to the main text.

[`assets/foods/generation.json`](../articles/cn/assets/foods/generation.json).
The editorial image prompt is in
[`vegetable-editorial.prompt.txt`](../articles/cn/assets/vegetable-editorial.prompt.txt).
These files preserve the actual prompts; this document defines the reusable method.

## Choose the comparison

| Question | Preferred display | Required conditions |
| --- | --- | --- |
| How much of one nutrient? | Sorted horizontal bars and an exact data table | Zero baseline, units, edible weight, preparation state |
| What does a serving contribute? | A labelled portion switch or side-by-side portion view | Explicit example weights; no hidden weight changes |
| How do several nutrients compare? | A single matrix of values and small bars | Independent column scales and units are stated |
| How do vitamin profiles differ? | A few representative vitamins as percentages of one reference system | Name the reference system, units and population; retain absolute amounts |
| How is a meal divided? | Stacked proportions with a labelled legend | Segment lengths computed from actual weights |
| How does a mechanism change an outcome? | A small explanatory diagram | State the input and assumptions, such as equal calcium intake |

Choose distinct, common ingredients across categories. Keep one named lettuce
example rather than several similar cultivars; include relevant foods such as
spinach. The representative entry does not describe every cultivar in its category.

Do not add arbitrary nutrient percentages into a universal food score. Explain
complementarity across fibre, representative vitamins, minerals, and actual
portions. If an established composite score is discussed, identify its selected
nutrients, weighting, energy denominator and limitations.

## Data and rendering

The reference implementation uses:

- [`data/vegetable-nutrients.json`](../data/vegetable-nutrients.json): selected
  USDA SR Legacy entries, FDC identifiers, exact descriptions, preparation states,
  nutrient identifiers and values, plus FDA comparison references.
- [`scripts/build_vegetable_visuals.py`](../scripts/build_vegetable_visuals.py):
  bilingual HTML figures, synchronized tables and standalone SVG overviews.
- [`vegetable-nutrition.css`](../articles/cn/vegetable-nutrition.css): the warm
  paper, deep green and restrained rust/gold chart treatment.
- [`vegetable-nutrition.js`](../articles/cn/vegetable-nutrition.js): optional
  portion switching. The initial chart and tables work without JavaScript.
- [`assets/foods/`](../articles/cn/assets/foods/): shared ingredient cutouts.
  English pages reuse the same assets; labels and explanations are localized.

Standalone SVGs embed ingredient PNGs as data URLs so the downloaded chart does
not depend on accompanying files. The article itself uses small shared PNG files.
Visible food names supply thumbnail labels; redundant thumbnail alt text can be
empty. All numerical values remain available as readable text or tables.

Percentages use unrounded snapshot values. Round only the displayed result, state
that rounding occurs, and avoid floating-point rounding artefacts. If a bar is
capped at 100%, retain the actual percentage in the label and explain the cap.

## Rebuild

```bash
python3 scripts/build_vegetable_visuals.py
python3 scripts/build.py
python3 -m unittest discover -s tests
node --check articles/cn/vegetable-nutrition.js
```

For updated downloadable PNGs on macOS, use this command before the site build:

```bash
python3 scripts/build_vegetable_visuals.py --png
```

The optional PNG export uses Quick Look and Pillow. It pads the SVG to a square
for thumbnail rendering, then removes only that padding; it does not crop chart
content. The normal site build uses committed outputs and needs neither tool.

## Verify before publishing

- Check every image against its food label, especially similar ingredients.
- Check transparency and legibility on the article's actual background.
- Verify values against the snapshot, including raw/cooked and edible weights.
- Check both languages, all local built-page asset links, and download links.
- Check a narrow viewport: the page stays within the viewport, while wide
  matrices scroll inside their own labelled containers.
- Exercise portion switching; ensure values, weights and bar lengths agree.
- Keep tables available without JavaScript and verify generation is repeatable.
- Inspect the complete exported image, including rightmost columns and footnotes.
- Follow the existing commit/push authorization for the task after checks pass.
